# Web-приложение управляющей компании

Frontend на Nuxt 4, Vue 3 и JavaScript для работы с заявками, пользователями, жалобами, сообщениями, объявлениями и информацией по домам.

## Локальный запуск

Нужен Node.js 24. Зависимости зафиксированы в `package-lock.json`.

```powershell
npm ci
npm run dev
```

Параметры подключения можно задать в `.env` по примеру `.env.example`. По умолчанию API находится на `http://127.0.0.1:8000/api/v1`.

## Сборка и проверки

```powershell
npm test
npm run build
node .output/server/index.mjs
```

Тесты проверяют адреса WebSocket для локального запуска, серверного адреса, HTTPS и размещения под общим reverse proxy.

## Docker

Dockerfile собирает приложение в отдельном этапе и запускает только `.output` от непривилегированного пользователя. `.env`, исходные локальные зависимости и кэш не попадают в образ.

Общий `docker-compose.yml` и подробная инструкция `DEPLOYMENT.md` находятся в соседнем каталоге `uk_backend`. Обычно оба репозитория располагаются рядом.

При контейнерном запуске:

- `NUXT_PUBLIC_API_BASE=/api/v1`: браузер обращается к API через Nginx на адресе открытого сайта.
- `NUXT_API_INTERNAL_BASE=http://backend:8000/api/v1`: серверная часть Nuxt обращается к backend внутри Docker-сети.
- `NUXT_PUBLIC_APP_NAME`: начальное название приложения.

Переменные задаются при запуске контейнера. Адреса API не нужно зашивать в сборку для каждого тестового сервера. WebSocket использует тот же публичный адрес, а фотографии доступны через `/static/`.
